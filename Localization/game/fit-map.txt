# Fit map of the l10n-check fit rule (M003 D097): which box, area or tooltip every ELK key is drawn in.
# One line per key family, first match wins; the lines that share the first match's glob all apply, so a key
# shown in two places is measured in both. `#` starts a comment; a glob is lowercase, `*` stops at `/`,
# `**` runs across `/`, and `[0-9]+` is a run of digits.
#   box <glob> <Data/UI layout> <ElementID>[#n]   the box of that element: WindowSize minus the TextPos inset the
#                                                 TextAlign takes, FontSize 0/1/2 = small/medium/large, default
#                                                 medium (UIBasic.cpp). `#n` is the n-th element with that ID.
#   area <glob> <W>x<H> <font>                    text C++ code places in a rectangle no layout holds (an estimate
#                                                 where the line says so)
#   tooltip <glob>                                the hint drawn in the medium font, wrapped at 300
#                                                 line space, any height (SceneInternal.cpp SetToolTip)
#   scroll <glob> # <reason>                      text in a UI_SCROLL_TEXT: it scrolls, so it is not measured
# The first part holds one exact line per TextKey or ToolTip reference of Data/UI (layout order lost on
# purpose: generated once, edited by hand after). The families below it cover every other key of
# Data/ELK/game_data_base.
