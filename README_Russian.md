# Где сейчас проект (ноябрь 2026)

Сам перенос в основном завершён: игра работает нативно в Windows, macOS и Linux, говорит на десяти языках, и все редакторы перенесены. Сейчас проект упёрся в графику — в повёрнутые виды зданий и предметов. См. «Стена: графика» ниже.


# Что сделано

**Игра**

- Здесь вся одиночная игра и её данные, собранные командой `zig build` (Zig + clang) как нативная 64-битная программа. Кампании, обучение и случайные миссии проходимы, включая сохранение и загрузку, видео и звук.

- Движок ушёл с Win32 и DirectX на переносимый слой: SDL3 для окон, ввода и звука и рендерер SDL GPU.

- Закрытые библиотеки убраны: FMOD, Bink и Stingray удалены. Звук и видео теперь используют Ogg Vorbis и Ogg Theora.

- StreamIO.dll, слой хранения данных движка, заменена реализацией на Zig (`Sources/src/StreamIOZig`).

- Старый код C++ компилируется в clang с UBSan, что выявило и исправило десятки ошибок, которые сборка 2003 года молча терпела.

- Оригинальные случайные миссии возвращены, и каждая глава кампании открывает свою историческую миссию, как задумано в её сценарии.

- Профили игроков могут переходить за игроком с машины на машину через облачную синхронизацию.

- Сетевая игра по локальной сети работает. Код GameSpy удалён, игра через интернет пока не подключена.

**Десять языков**

- Игра, все редакторы, утилиты командной строки с их руководствами и этот README доступны на английском, русском, китайском (упрощённом), хинди, испанском, французском, немецком, португальском (Бразилия), японском и индонезийском.

- Девять переводов устанавливаются как языковые моды с новым текстовым движком TrueType, который рисует все эти письменности.

- Переводы сделаны машиной и всё ещё нуждаются в проверке носителями языка. Исправления приветствуются.

**Все редакторы**

- Редактор карт, Редактор ресурсов со всеми его подредакторами и ELK, набор для локализации, переписаны как приложения на Zig с Dear ImGui (`Sources/editor`). Они общаются с движком на C++ через C ABI (`Sources/src/EditorBridge`).

- Старые редакторы MFC, работавшие только в Windows, удалены. Игра читает то, что пишут новые редакторы, и тесты проверяют это собственными средствами чтения игры.

- Старые утилиты командной строки заменены семью переносимыми для создания модов: `bk-pak`, `bk-table`, `bk-image`, `bk-video`, `bk-font`, `bk-map` и `bk-sprite`. См. `tools/guide/README.md`.

**Опция Remastered**

- Options > Settings > Gameplay > Remastered по умолчанию выключена, и в выключенном виде играют по оригинальным правилам. Включённая добавляет возможности, которых не было в игре 2003 года, например поворот камеры в четыре шага, поиск самого быстрого маршрута и перемещение пехоты прямо из одного контейнера в другой.

- Повторы миссий в разработке; их основа уже влита.


# Стена: графика

Поворот камеры означает, что каждое здание и каждый предмет нужно показывать с четырёх сторон, но графика 2003 года — это набор изображений каждого объекта только с одной стороны. Остальные стороны никогда не рисовались.

Пока я пробовал два подхода для всех 412 объектов:

- Построение каждого повёрнутого изображения из пикселей 2003 года (оставлено 2026-10-29: каждая решённая проблема порождала новую).

- Отрисовка простых 3D-моделей, раскрашенных по тем же изображениям. Так проект работает сегодня. Сторона, которую показывает графика 2003 года, выглядит правильно, но всё, чего она никогда не показывала, приходится угадывать. Детали тоже не удаются: слуховое окно, нарисованное на плоской крыше, не может выглядеть правильно с другой стороны.

Ни то, ни другое не годится. Правильный путь — настоящая 3D-модель каждого объекта, где детали вроде слуховых окон выполнены настоящей геометрией, а на каждой плоской грани лежит текстура, так что любая сторона следует из формы.

Вопрос в том, откуда взять эти модели и текстуры:

- Моделировать их вручную или с помощью агентов по проектам 2003 года.

- Модели Blitzkrieg 2, которые Nival тоже опубликовала. Пробный рендер показывает, что они устроены именно так и выглядят чисто при всех четырёх поворотах, но многие из них — другие здания, чем одноимённые из 2003 года, а лицензия явно не охватывает их графику.

- Генераторы 3D по изображению, которые я на этой графике не пробовал.

Решение не принято. Если вы 3D-художник или знакомы с такой работой, я буду рад услышать вас.

# Поддерживаемые платформы

Цель задаётся параметром `-Dtarget=`. Собранное дерево раскладывается как `zig-out/game/<os>/<arch>/<config>`, поэтому несколько целей и оба уровня оптимизации лежат рядом.

| Платформа | Целевая тройка | Состояние |
| --- | --- | --- |
| Windows (MSVC) | `x86_64-windows-msvc` | Игра и редакторы работают; проверено в CI |
| macOS (Apple Silicon) | `aarch64-macos` | Игра и редакторы работают; проверено в CI |
| Linux (x86_64) | `x86_64-linux-gnu` | Игра и редакторы работают; проверено в CI на программном рендерере |
| macOS (Intel) | `x86_64-macos` | Собирается; у раннера CI нет GPU для игры, поэтому игра проверяется на настоящем Mac с Intel |
| Linux (arm64, Raspberry Pi) | `aarch64-linux-gnu` | Только тесты платформы; игра и редакторы пока не проверены |
| Windows (MinGW) | `x86_64-windows-gnu` | Только тесты платформы; движок здесь пока не компилируется |

CI запускает каждую цель на раннере собственной архитектуры, поэтому наборы тестов выполняются, а не просто компонуются. Некоторые задания на Linux и macOS сейчас падают.

В Linux значок окна задаётся в самой программе, и X11 с KDE его учитывают. GNOME на Wayland его игнорирует и берёт значок для панели и alt-tab из записи рабочего стола, названной по app id программы (`org.blitzkrieg.game`, а для редакторов `org.blitzkrieg.mapeditor`, `org.blitzkrieg.resourceeditor`, `org.blitzkrieg.elk`). В установку входит необязательный скрипт, который записывает эти записи и значок в `~/.local/share`; сам по себе он не запускается. Из папки установки выполните `Tools/install_desktop_entry.sh` (из копии репозитория: `tools/install_desktop_entry.sh [install-dir]`), а `Tools/install_desktop_entry.sh --remove` отменяет это.

Установка Visual Studio нужна только для `x86_64-windows-msvc`. Для всех остальных целей, включая MinGW, Zig поставляет собственные инструменты, заголовки и библиотеки импорта.


# Сборка и запуск

1. Клонируйте репозиторий с подмодулями или выполните `git submodule update --init --recursive` в существующей копии.

2. Установите Zig 0.17. Для `x86_64-windows-msvc` также нужны набор инструментов MSVC и Windows SDK (пути настраиваются параметрами `-Dmsvc-include`/`-Dwindows-sdk-include` и их аналогами для `lib`, если они отличаются от значений по умолчанию в `build.zig`).

3. Выполните `zig build install-all -Dtarget=<triple> --release=fast`, чтобы получить игру, девять языковых модов и все редакторы, или `zig build install-game` только для игры. Без `-Dtarget` сборка делается для хоста, а без `--release=fast` получится отладочная сборка.

4. Запустите собранный файл, например `zig-out/game/windows/x86_64/release/Game.exe` в Windows или `zig-out/game/macos/arm64/release/Game` на Apple Silicon (`.../debug/...` без `--release=fast`). Игра запускается в окне; `-fullscreen` доступен как параметр командной строки.

5. `zig build package` создаёт распространяемые zip-пакеты, а `zig build --help` перечисляет все шаги и тесты.
