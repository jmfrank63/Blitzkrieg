Этот репозиторий — личный проект Йоханнеса Марии Франка. Я использую его для удовольствия и обучения, в первую очередь чтобы практиковать агентное программирование на существующих приложениях (brownfield). Исходный README сохранён в `readme_original`.

Предупреждение: проект находится в разработке.


# Что этот репозиторий умеет сегодня

- Содержит полный исходный код одиночной игры Blitzkrieg и игровые данные.

- Собирает всю игру командой `zig build` (Zig + clang) для шести целей — Windows (MSVC и MinGW), macOS (Intel и Apple Silicon) и Linux (x86_64 и arm64) — и создаёт готовую к запуску установку в `zig-out/game/<os>/<arch>/<config>`. Visual Studio нужна только для цели MSVC; для остальных Zig приносит собственный набор инструментов.

- Собирается и запускается как нативный **64-битный** Game.exe (`zig build install-game -Dtarget=x86_64-windows-msvc`); 32-битные цели прекращены. Миссии кампании и обучение проходимы в x64, включая сохранение и загрузку, видео и звук.

- Поставляется с StreamIO.dll, полностью замещённой реализацией на Zig (`Sources/src/StreamIOZig`) — всем слоем хранения данных движка: двоичные графы объектов для сохранения и загрузки, деревья данных XML, фабрика объектов, глобальные переменные, консоль и настройки.

- Компилирует старый код C++ в clang с включённым UBSan, что выявило и исправило десятки скрытых ошибок, которые сборка MSVC 2003 года молча терпела, — в том числе 22-летний сбой вызова чисто виртуальной функции при уничтожении танка и башни.

- Проверяет каждую поддерживаемую цель в CI, запуская тесты платформы нативно на собственном раннере — Linux x86_64 и arm64, Windows MSVC и MinGW, macOS Intel и Apple Silicon, — а не только кросс-компилируя.

- По-прежнему чисто собирается из исходного решения `A7.sln` современными инструментами MSVC (`Debug | Win32`) как эталон поведения.

- По умолчанию запускается в настоящем окне, а `-fullscreen` остаётся параметром командной строки.

- Использует подмодули Git для недостающих библиотек.

- Поддерживает отладку нативного C++ и WinDbg в VS Code Insiders, а также скрипты перехвата сбоев без интерфейса в `tools/zig/`.

- Предоставляет вспомогательный процесс упаковки сжатых видеоресурсов в `VideoAssets/`.

- Убрана старая обработка сбоев BugSlay, вместо неё используются стандартные assert из C++.

# Поддерживаемые платформы

`zig build` принимает шесть целей. Цель задаётся параметром `-Dtarget=`; собранное дерево раскладывается как `zig-out/game/<os>/<arch>/<config>`, поэтому несколько целей и оба уровня оптимизации лежат рядом и не перезаписывают друг друга.

| Платформа | Целевая тройка | Состояние |
| --- | --- | --- |
| Windows (MSVC) | `x86_64-windows-msvc` | Играбельно |
| macOS (Apple Silicon) | `aarch64-macos` | Играбельно |
| macOS (Intel) | `x86_64-macos` | Собирается; не проверено игрой |
| Linux (x86_64) | `x86_64-linux-gnu` | В разработке |
| Linux (arm64, Raspberry Pi) | `aarch64-linux-gnu` | Только слой платформы |
| Windows (MinGW) | `x86_64-windows-gnu` | Только слой платформы |

«Только слой платформы» означает, что цель собирается и проходит тесты платформы, но полная сборка игры на ней пока не запущена.

Установка Visual Studio нужна только для `x86_64-windows-msvc`. Для всех остальных целей, включая MinGW, Zig поставляет собственные инструменты, заголовки и библиотеки импорта.

Каждая цель проверяется рабочим процессом `Cross-platform validation` на раннере собственной архитектуры, поэтому наборы тестов выполняются, а не просто компонуются.


# Запуск игры через Zig (основной способ)

1. Клонируйте репозиторий с подмодулями или выполните `git submodule update --init --recursive` в существующей копии.

2. Установите Zig (0.17 или новее). Для `x86_64-windows-msvc` также нужны набор инструментов MSVC и Windows SDK (пути настраиваются параметрами `-Dmsvc-include`/`-Dwindows-sdk-include` и их аналогами для `lib`, если они отличаются от значений по умолчанию в `build.zig`). Другим целям они не нужны.

3. Выполните `zig build install-game -Dtarget=<triple> --release=fast`, чтобы играть, или уберите `--release=fast` для отладочной сборки. Без `-Dtarget` сборка делается для хоста.

4. Запустите собранный файл — `zig-out/game/windows/x86_64/release/Game.exe` в Windows, `zig-out/game/macos/arm64/release/Game` на Apple Silicon (`.../debug/...` без `--release=fast`). Дерево названо по содержащейся оптимизации, поэтому они никогда не перезаписывают друг друга.

5. `zig build package` создаёт распространяемые zip-пакеты; `zig build test` запускает модульные тесты Zig и дымовой тест ABI C++.


# Запуск игры через Visual Studio 2026 Insiders

1. Клонируйте репозиторий с подмодулями или выполните `git submodule update --init --recursive` в существующей копии.

2. Установите Visual Studio 2026 Insiders / Visual Studio 18 с рабочей нагрузкой «Разработка классических приложений на C++», набором инструментов MSVC из VS 2026 и Windows 10 или Windows 11 SDK.

3. Откройте `Sources/src/A7.sln`.

4. Выберите `Debug | Win32`.

5. Соберите проект `Game` или всё решение.

6. Запустите проект `Game` клавишей F5 или напрямую `Sources/src/Game/Debug/Game.exe`.

7. По умолчанию игра запускается в окне. Добавьте `-fullscreen` в аргументы командной строки проекта `Game`, если нужно прежнее полноэкранное поведение.

Если сборка не может скопировать DLL в `Sources/src/Game/Debug`, закройте работающий процесс `Game.exe` и соберите снова.


# История на сегодня

- Найдены недостающие библиотеки и добавлены как подмодули Git.

- Развёрнута виртуальная машина Windows XP SP3 с Visual Studio 6, чтобы изучить исходную среду.

- VS 6 была нестабильна и часто падала, поэтому усилия сместились на современные инструменты.

- Установлена Visual Studio 2010, старый проект `.dwr` преобразован в `.sln`.

- Решение загружено в VS 2026 Insiders, все зависимости обновлены.

- Две недели агентного программирования привели к тому, что решение собирается с нуля без ошибок и предупреждений.

- Отладка во время выполнения продвинулась дальше начального меню: обучение загружается и проходимо, включая выбор и перемещение танка.

- Разработка перенесена в VS Code Insiders ради лучших инструментов.

- Настроены два пути отладки: нативный C++ и WinDbg.

- BugSlay удалён, потому что мешал отладке и в одном случае упал после сбоя.

- BugSlay заменён простыми стандартными assert из C++.

- Без BugSlay проект готов к целенаправленной отладке во время выполнения на пути к полному запуску.

- Сборка переведена на Zig: `build.zig` компилирует каждый проект в clang, компонует с набором инструментов MSVC и раскладывает готовую к запуску игру.

- StreamIO.dll — слой хранения данных и служб движка — заменена реализацией на Zig с мостом ABI C++, попутно исправлены формат графа объектов при сохранении и загрузке, чтение и запись XML, настройки и падения производительности на кадр.

- Игра стала проходимой от начала до конца под сборкой Zig: кампании, обучение, абордаж, авиация, циклы сохранения и загрузки, синхронное видео, верная миникарта в современных разрешениях.

- Игра перенесена на 64 бита: исправлены усечения указателей в рендерере, вызовы `_control87` эпохи x87, `#pragma pack(1)` на типах STL, встроенный ассемблер x86 (заменён переносимыми интринсиками SSE), канал указателей юнитов Lua и идентификаторы объектов формата сохранений.

- Сборка x64 проверена игрой через обучение, сбой за сбоем, а UBSan превращал каждое 20-летнее неопределённое поведение в точный файл и строку: координаты миникарты, хеширование построений, расчёт угла бомбардировки и другое.

- Проект ушёл с Win32 на переносимый слой платформы: SDL3 для окон, ввода и звука, рендерер SDL GPU вместо пути DirectX и небольшой нативный адаптер на каждую операционную систему.

- Игра запущена на macOS, где она играбельна на Apple Silicon, затем последовал Linux.

- Добавлены цели Linux arm64 (класс Raspberry Pi) и Windows GNU ABI (MinGW), для чего во всей сборке пришлось разделить «это Windows?» и «это Visual Studio?». Выяснилось, что Intel macOS собирался вообще без своих адаптеров Cocoa, что задача Linux была красной из-за отсутствия среды выполнения C и что пути C++ для Linux были привязаны к мультиархитектурной тройке x86_64.

- Все шесть целей поставлены под CI, каждая на раннере собственной архитектуры.
