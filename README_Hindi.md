यह रिपॉज़िटरी Johannes Maria Frank का एक निजी शौकिया प्रोजेक्ट है। मैं इसे मज़े और सीखने के लिए इस्तेमाल करता हूँ, खासकर मौजूदा (ब्राउनफ़ील्ड) एप्लिकेशन पर एजेंट-आधारित कोडिंग का अभ्यास करने के लिए। मूल README `readme_original` में सुरक्षित है।

चेतावनी: यह प्रोजेक्ट अभी विकास के अधीन है।


# यह रिपॉज़िटरी आज क्या कर सकती है

- इसमें Blitzkrieg के सिंगल-प्लेयर का पूरा सोर्स कोड और गेम डेटा शामिल है।

- `zig build` (Zig + clang) से पूरा गेम छह टारगेट के लिए बनाती है — Windows (MSVC और MinGW), macOS (Intel और Apple Silicon) और Linux (x86_64 और arm64) — और `zig-out/game/<os>/<arch>/<config>` के अंतर्गत चलने योग्य इंस्टॉल लेआउट तैयार करती है। केवल MSVC टारगेट को Visual Studio चाहिए; बाकी के लिए Zig अपना टूलचेन साथ लाता है।

- नेटिव **64-बिट** Game.exe के रूप में बनती और चलती है (`zig build install-game -Dtarget=x86_64-windows-msvc`); 32-बिट टारगेट बंद कर दिए गए हैं। कैंपेन मिशन और ट्यूटोरियल x64 में खेले जा सकते हैं, जिनमें सेव/लोड, वीडियो और ध्वनि शामिल हैं।

- StreamIO.dll को पूरी तरह Zig इम्प्लीमेंटेशन से बदलकर भेजी जाती है (`Sources/src/StreamIOZig`) — इंजन की पूरी परसिस्टेंस परत: सेव/लोड के लिए बाइनरी ऑब्जेक्ट ग्राफ़, XML डेटा ट्री, ऑब्जेक्ट फ़ैक्टरी, ग्लोबल वेरिएबल, कंसोल और ऑप्शन।

- पुराने C++ को clang और UBSan चालू करके कंपाइल करती है, जिससे दर्जनों छिपी हुई गलतियाँ सामने आईं और ठीक हुईं, जिन्हें 2003 का MSVC बिल्ड चुपचाप सह लेता था — इनमें टैंक/बुर्ज के टियरडाउन में 22 साल पुराना शुद्ध-वर्चुअल कॉल क्रैश भी है।

- हर समर्थित टारगेट को CI में जाँचती है, और प्लेटफ़ॉर्म टेस्ट सूट को केवल क्रॉस-कंपाइल करने के बजाय उसके अपने रनर पर नेटिव रूप से चलाती है — Linux x86_64 और arm64, Windows MSVC और MinGW, macOS Intel और Apple Silicon।

- व्यवहार के संदर्भ के रूप में अब भी मूल `A7.sln` सॉल्यूशन से आधुनिक MSVC टूल्स में साफ़ बनती है (`Debug | Win32`)।

- डिफ़ॉल्ट रूप से असली विंडो में चलती है, और `-fullscreen` कमांड-लाइन विकल्प के रूप में उपलब्ध रहता है।

- लापता लाइब्रेरी के लिए Git सबमॉड्यूल इस्तेमाल करती है।

- VS Code Insiders में नेटिव C++ और WinDbg डीबगिंग के साथ `tools/zig/` में बिना इंटरफ़ेस वाली क्रैश-कैप्चर स्क्रिप्ट का समर्थन करती है।

- `VideoAssets/` के अंतर्गत संपीड़ित मूवी एसेट की पैकेजिंग के लिए सहायक वर्कफ़्लो देती है।

- पुराने BugSlay क्रैश हैंडलिंग को हटाकर उसकी जगह मानक C++ assert लगाए गए हैं।

# समर्थित प्लेटफ़ॉर्म

`zig build` छह टारगेट स्वीकार करता है। `-Dtarget=` से एक दें; बना हुआ ट्री `zig-out/game/<os>/<arch>/<config>` के रूप में सजता है, इसलिए कई टारगेट और दोनों ऑप्टिमाइज़ेशन स्तर एक-दूसरे को ओवरराइट किए बिना साथ-साथ रहते हैं।

| प्लेटफ़ॉर्म | टारगेट ट्रिपल | स्थिति |
| --- | --- | --- |
| Windows (MSVC) | `x86_64-windows-msvc` | खेलने योग्य |
| macOS (Apple Silicon) | `aarch64-macos` | खेलने योग्य |
| macOS (Intel) | `x86_64-macos` | बनता है; खेलकर परखा नहीं गया |
| Linux (x86_64) | `x86_64-linux-gnu` | विकासाधीन |
| Linux (arm64, Raspberry Pi) | `aarch64-linux-gnu` | केवल प्लेटफ़ॉर्म परत |
| Windows (MinGW) | `x86_64-windows-gnu` | केवल प्लेटफ़ॉर्म परत |

“केवल प्लेटफ़ॉर्म परत” का मतलब है कि टारगेट बनता है और प्लेटफ़ॉर्म टेस्ट सूट पास करता है, लेकिन उस पर पूरा गेम बिल्ड अभी शुरू नहीं किया गया है।

केवल `x86_64-windows-msvc` को Visual Studio इंस्टॉलेशन चाहिए। MinGW सहित हर दूसरे टारगेट के लिए Zig अपना टूलचेन, हेडर और इम्पोर्ट लाइब्रेरी खुद देता है।

हर टारगेट को `Cross-platform validation` वर्कफ़्लो अपने ही आर्किटेक्चर के रनर पर चलाता है, ताकि सूट केवल लिंक न हों बल्कि सचमुच चलें।


# Zig से गेम चलाना (मुख्य तरीका)

1. रिपॉज़िटरी को सबमॉड्यूल के साथ क्लोन करें, या मौजूदा चेकआउट में `git submodule update --init --recursive` चलाएँ।

2. Zig (0.17 या नया) इंस्टॉल करें। `x86_64-windows-msvc` के लिए MSVC टूलचेन और Windows SDK भी चाहिए (यदि आपके पथ `build.zig` के डिफ़ॉल्ट से अलग हैं तो उन्हें `-Dmsvc-include`/`-Dwindows-sdk-include` और उनके `lib` समकक्षों से बदला जा सकता है)। किसी और टारगेट को इनकी ज़रूरत नहीं।

3. खेलने के लिए `zig build install-game -Dtarget=<triple> --release=fast` चलाएँ, या डीबग बिल्ड के लिए `--release=fast` हटा दें। `-Dtarget` छोड़ने पर होस्ट के लिए बनता है।

4. बने हुए बाइनरी को चलाएँ — Windows पर `zig-out/game/windows/x86_64/release/Game.exe`, Apple Silicon पर `zig-out/game/macos/arm64/release/Game` (`--release=fast` के बिना `.../debug/...`)। ट्री का नाम उसमें मौजूद ऑप्टिमाइज़ेशन के अनुसार होता है, इसलिए दोनों कभी एक-दूसरे को ओवरराइट नहीं करते।

5. `zig build package` वितरण योग्य zip पैकेज बनाता है; `zig build test` Zig यूनिट टेस्ट और C++ ABI स्मोक टेस्ट चलाता है।


# Visual Studio 2026 Insiders से गेम चलाना

1. रिपॉज़िटरी को सबमॉड्यूल के साथ क्लोन करें, या मौजूदा चेकआउट में `git submodule update --init --recursive` चलाएँ।

2. Visual Studio 2026 Insiders / Visual Studio 18 को “Desktop development with C++” वर्कलोड, VS 2026 MSVC टूलचेन और Windows 10 या Windows 11 SDK के साथ इंस्टॉल करें।

3. `Sources/src/A7.sln` खोलें।

4. `Debug | Win32` चुनें।

5. `Game` प्रोजेक्ट बनाएँ, या पूरा सॉल्यूशन बनाएँ।

6. `Game` प्रोजेक्ट को F5 से चलाएँ, या `Sources/src/Game/Debug/Game.exe` सीधे चलाएँ।

7. गेम डिफ़ॉल्ट रूप से विंडो में शुरू होता है। पुराना फ़ुलस्क्रीन व्यवहार चाहिए तो `Game` प्रोजेक्ट के कमांड आर्गुमेंट में `-fullscreen` जोड़ें।

यदि कोई बिल्ड `Sources/src/Game/Debug` में DLL कॉपी नहीं कर पाता, तो चल रही किसी भी `Game.exe` प्रक्रिया को बंद करें और फिर से बनाएँ।


# अब तक का इतिहास

- लापता लाइब्रेरी खोजी गईं और उन्हें Git सबमॉड्यूल के रूप में जोड़ा गया।

- मूल वातावरण को समझने के लिए Visual Studio 6 वाली Windows XP SP3 वर्चुअल मशीन बनाई गई।

- VS 6 अस्थिर था और अक्सर क्रैश होता था, इसलिए प्रयास आधुनिक टूल की ओर मुड़ गया।

- Visual Studio 2010 इंस्टॉल किया गया और पुराने `.dwr` प्रोजेक्ट को `.sln` में बदला गया।

- सॉल्यूशन को VS 2026 Insiders में लोड किया गया और सभी निर्भरताएँ अपडेट की गईं।

- दो सप्ताह की एजेंट-आधारित कोडिंग पूरी हुई, ताकि सॉल्यूशन साफ़ स्थिति से बिना किसी त्रुटि और चेतावनी के कंपाइल हो।

- रनटाइम डीबगिंग अब शुरुआती मेनू से आगे बढ़ चुकी है: ट्यूटोरियल लोड होता है और खेलने योग्य है, जिसमें टैंक चुनना और चलाना भी शामिल है।

- बेहतर टूल के लिए विकास VS Code Insiders में ले जाया गया।

- दो डीबग रास्ते सेट किए गए: नेटिव C++ और WinDbg।

- BugSlay हटाया गया क्योंकि उसने डीबगिंग को कठिन बना दिया था और एक मामले में वह एक क्रैश के बाद खुद क्रैश हुआ।

- BugSlay की जगह सरल मानक C++ assert लगाए गए।

- BugSlay हटने के बाद प्रोजेक्ट पूरी तरह चलने की दिशा में केंद्रित रनटाइम डीबगिंग के लिए तैयार है।

- बिल्ड को Zig पर ले जाया गया: `build.zig` हर प्रोजेक्ट को clang से कंपाइल करता है, MSVC टूलचेन से लिंक करता है और चलने योग्य गेम लेआउट तैयार करता है।

- StreamIO.dll — इंजन की परसिस्टेंस और सेवा परत — को Zig इम्प्लीमेंटेशन और C++ ABI ब्रिज से बदला गया, और इस दौरान सेव/लोड ऑब्जेक्ट-ग्राफ़ फ़ॉर्मेट, XML पढ़ना/लिखना, ऑप्शन और प्रति-फ़्रेम प्रदर्शन गिरावट ठीक की गईं।

- Zig बिल्ड में गेम को शुरू से अंत तक खेलने योग्य बनाया गया: कैंपेन, ट्यूटोरियल, बोर्डिंग, विमानन, सेव/लोड राउंड-ट्रिप, तालमेल में वीडियो और आधुनिक रिज़ॉल्यूशन पर सही मिनीमैप।

- गेम को 64-बिट पर पोर्ट किया गया: रेंडरर में पॉइंटर ट्रंकेशन, x87 युग की `_control87` कॉल, STL टाइप पर `#pragma pack(1)`, x86 इनलाइन असेंबली (जिसे पोर्टेबल SSE इंट्रिन्सिक से बदला गया), Lua यूनिट-पॉइंटर चैनल और सेव फ़ॉर्मेट के ऑब्जेक्ट ID ठीक किए गए।

- x64 बिल्ड को ट्यूटोरियल में क्रैश-दर-क्रैश खेलकर परखा गया, और UBSan ने 20 साल पुराने हर अपरिभाषित व्यवहार को सटीक फ़ाइल और पंक्ति में बदल दिया: मिनीमैप निर्देशांक, फ़ॉर्मेशन हैशिंग, बमबारी कोण की गणना और बहुत कुछ।

- Win32 से हटकर पोर्टेबल प्लेटफ़ॉर्म परत अपनाई गई: विंडो, इनपुट और ऑडियो के लिए SDL3, DirectX रास्ते की जगह SDL GPU रेंडरर, और हर ऑपरेटिंग सिस्टम के लिए एक छोटा नेटिव एडैप्टर।

- गेम को macOS पर चालू किया गया, जहाँ वह Apple Silicon पर खेलने योग्य है, और Linux उसके बाद आया।

- Linux arm64 (Raspberry Pi श्रेणी) और Windows GNU ABI (MinGW) को टारगेट के रूप में जोड़ा गया, जिसके लिए पूरे बिल्ड में “क्या यह Windows है?” को “क्या यह Visual Studio है?” से अलग करना पड़ा। इससे पता चला कि Intel macOS बिना किसी Cocoa एडैप्टर के कंपाइल हो रहा था, Linux जॉब C रनटाइम न होने से लाल था, और Linux के C++ रास्ते x86_64 मल्टीआर्क ट्रिपल से बंधे थे।

- छहों टारगेट CI के अंतर्गत लाए गए, हर एक अपने ही आर्किटेक्चर के रनर पर।


# रोडमैप

1. बाकी ट्यूटोरियल और कैंपेन में 64-बिट बिल्ड को स्थिर करना पूरा करना।

2. Linux arm64 और MinGW पर पूरा गेम बिल्ड चालू करना — आज केवल उनकी प्लेटफ़ॉर्म परतें जाँची गई हैं — और Intel macOS को खेलकर परखना।

3. 32-बिट सेव गेम को 64-बिट फ़ॉर्मेट में बदलने वाली उपयोगिता बनाना।

4. FMOD, Stingray और Bink की जगह ओपन-सोर्स विकल्प लाना।

5. StreamIO पोर्ट को आदर्श मानकर C++ प्रोजेक्ट को एक-एक करके Zig कोड से बदलते रहना।
