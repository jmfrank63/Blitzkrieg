# P04-M03 — restore with GFX-preserving merge

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans`; stop after this packet.

**Objective:** Restore settings from another machine without importing its monitor layout.

**Dependencies:** P04-M02.

**Allowed files:** `Sources/src/CloudSync/backup.zig`, `Sources/src/CloudSync/backup_test.zig`, `Sources/src/CloudSync/cloudsync.zig`, `Sources/src/CloudSync/CloudSync.def`, `Sources/src/CloudSync/CloudSync.x64.def`, `tools/zig/cloudsync_abi_test.cpp`.

This packet is Zig and ABI only. Applying a staged restore at startup is C++ and belongs to `P06-M02`; no file under `Sources/src/Game` or `Sources/src/GameTT` is touched here.

- [ ] Write the failing test with a backup whose `GFX.*` values differ from local, asserting they are not adopted in merge mode.
- [ ] **Stage the restore; do not write `config.cfg` under a running game.** The game rewrites that file from its in-memory options at shutdown (`GameMain.cpp:1182`) and from any of eight other `SerializeConfig( false, ... )` call sites across the interface code, so a restored file written mid-session is discarded before the player ever sees it.
- [ ] Implement `restore(allocator, ctx, entry_id, mode: RestoreMode) !void` with `RestoreMode = enum { merge_keep_local_gfx, full }`, defaulting to the merge. It downloads the chosen backup into a staged directory and **touches nothing else** — in particular not `config.cfg`.
- [ ] **Stage as one atomic transaction, in its own directory.** A payload file plus a separate mode marker is two writes, and a crash between them leaves a stage that is either unreadable or, worse, readable with the wrong mode — applying merge content as a full restore or the reverse. Each restore builds `profiles/<name>/.cloudsync-restore/<nonce>/` holding `payload.cfg`, `meta.json` (mode, source entry id, payload SHA-256, nonce, creation time), and a `COMMIT` file written **last**. A stage without `COMMIT`, or whose payload does not match the hash in `meta.json`, is incomplete: it is ignored and deleted, never guessed at.
- [ ] **Never clear a valid stage to make room for a new one.** Writing into a fixed directory means a download that fails leaves the player with neither the old restore nor the new one. A new stage is built alongside the old, and the old remains the one that would apply until the new one is published.
- [ ] **Publish by atomically replacing an `ACTIVE` pointer, not by comparing timestamps.** Once two stage directories can both hold `COMMIT`, that marker says only "this stage is whole" — it cannot say which is current, so selecting the newest by `meta.json` creation time would pick wrongly under a clock rollback, equal timestamps, or coarse timestamp resolution. Write the chosen nonce to `.cloudsync-restore/ACTIVE.tmp` and rename it over `ACTIVE`; that rename is the single publication point and gives a genuine total order, last writer wins.
- [ ] Keep the two markers distinct and validate both: `COMMIT` plus the payload hash means the stage is complete, `ACTIVE` means it is the one to apply. A stage named by `ACTIVE` that fails its own validation is a hard error, not a reason to fall back to another stage — silently applying a restore the player did not choose is worse than refusing.
- [ ] Test two committed stages with equal timestamps and with reversed ones, asserting `ACTIVE` decides in both cases.
- [ ] **Tear down in the order `ACTIVE` first, directories second.** Deleting the stage directory before the pointer that names it leaves, for the width of a crash, an `ACTIVE` naming nothing — and the rule above turns that into a hard error on every subsequent launch, so a tidy-up ordering bug would brick startup. Removing `ACTIVE` first is a single atomic unlink; whatever survives after it is unreferenced debris.
- [ ] Distinguish the two failure shapes rather than treating both as fatal. A stage that **exists and fails validation** is a hard error: we were told to apply specific content and that content is wrong. An `ACTIVE` naming a directory that is **absent entirely** is unreachable through correct teardown, so it means outside interference or partial disk loss — clear `ACTIVE`, garbage-collect, log it, and report nothing staged. Neither case may apply a restore the player did not choose, but only one of them should stop the game from starting.
- [ ] Garbage-collect stage directories whenever `ACTIVE` is absent; that is the state a crash between the two removals leaves behind, and it is ordinary rather than exceptional.
- [ ] Crash-test both sides of the `ACTIVE` removal: after installing the config and before removing `ACTIVE` (the retry must be idempotent), and after removing `ACTIVE` but before the directories are gone (the next launch must report nothing staged and sweep them).
- [ ] Refuse a second restore while one is in flight. Two pollable jobs writing concurrently is the other way a fixed directory interleaves, and rejecting the second is honest where silently racing is not.
- [ ] **Merge at apply time, not at stage time.** Store the backup as fetched and let the apply step merge it against `config.cfg` as that file stands at the next startup. Merging early would freeze the local `GFX.*` values as they were when the player pressed restore, so a resolution changed later in the session would be quietly reverted.
- [ ] **Do not suppress the game's own config writes.** `config.cfg` and the staged restore are different files: a shutdown serialize is harmless because the stage is applied first at the next startup, and it is actively useful, since it carries any settings the player changed in the meantime into the merge. Suppression would discard binds and unrelated settings for no benefit — and with nine call sites, suppressing two of them would be arbitrary as well as wrong.
- [ ] Implement `mergeConfig(allocator, local_cfg, restored_cfg) ![]u8` taking every key from the backup **except** those under `GFX.`, which are kept from local.
- [ ] **Export the apply step, because the code that runs it is C++ and the merge lives here.** `bk_cloudsync_apply_pending_restore(profile: [*:0]const u8) i32` reads `ACTIVE`, validates the stage it names, snapshots, merges, writes `config.cfg` through temp-file-then-rename, and only then tears the stage down. Without it `P06-M02` would have to reimplement `mergeConfig` in C++ against the same config format — two implementations of one merge is how the two drift.
- [ ] **Make apply idempotent under a crash between the config rename and the stage cleanup.** That window is real: the next launch finds the stage still committed and applies it again. Re-merging is harmless — the content is the same both times — but a second undo snapshot is not, because it captures the *already restored* config and "undo the most recent" then recovers the restore instead of the original.
- [ ] Key the undo snapshot by the stage nonce, `.cloudsync-trash/config/<nonce>.cfg`, and **write it only if that file does not already exist**. A retried apply then reuses the first snapshot, and the original config stays recoverable however many times the apply is interrupted.
- [ ] Add the crash test explicitly: apply, simulate a crash after the `config.cfg` rename and before stage cleanup, apply again, and assert the undo snapshot is byte-identical to the pre-restore original rather than to the restored file.
- [ ] Make that export **purely local**: no daemon, no network, no credentials. It must succeed with rclone absent and cloud sync disabled, because a restore already requested and downloaded has to finish regardless of the feature's current state.
- [ ] Return a distinct code for "nothing staged" so startup can call it unconditionally and cheaply rather than probing the filesystem itself.
- [ ] Offer `full` but warn. It is survivable — a resolution absent from the local SDL mode list falls back to Auto, a disconnected monitor to display 0 — but both failures are silent, and silent is worse than refused.
- [ ] Restore is never automatic. Backups are pulled only on explicit player action; the cloud holds the history while the local machine keeps authority over its own display.
- [ ] Export `bk_cloudsync_backup_restore(entry_id, mode) i32`, pollable like any other network call. Own the whole export path.
- [ ] Commit checkpoint: `cloudsync: restore a config backup with a GFX-preserving merge`.

**Evidence:** Unit tests show a merge preserving local `GFX.Mode`, `GFX.Monitor`, and `GFX.FullScreen` while adopting every other key, a full restore adopting all, a merge computed against a `config.cfg` that changed after staging, a stage missing its `COMMIT` file discarded rather than applied, a failed download leaving the previous committed stage intact, and a crash-interrupted apply whose retry preserves the original undo snapshot.
