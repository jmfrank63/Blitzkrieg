## TestM3Fields flake: root cause found, fix waiting to be merged

**Root cause.** `STileTypeDesc::GetMapsIndex` (`fmtTerrain.h:87`) picks each tile variant with C `rand()`. `SeedFieldFills` (`session_fields.cpp`) never called `srand()`, so every fill was random.

**Fix.** On branch **`fix/m3-fields-flake`**, pushed:
- `9f19fb411` seeds `rand()` in `SeedFieldFills`. The test's exact-match strictness is restored and goes further than before: tile values match exactly, and two identical applies save byte-identical files.
- `26d16d51b` marks WINDOWS.md broken-window 4 fixed.

The fix passed 11 consecutive runs on macOS. It has not run in Windows CI yet.

**Merged** into `feat/map-editor-m3` by the orchestrator at handover, after resolving a WINDOWS.md ledger conflict: entry 4 is fixed and entry 5 open. After the merge (fee2c347b), `test-editor-bridge` was re-run: `M3 fields ok`, `editor-bridge: PASS`, rc=0.
