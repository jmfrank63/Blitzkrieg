# 999.6 Single-player replays — notes

Captured 2026-10-10. Decision: backlog (Johannes: "Not yet, but put it on the backlog. We want it later.").

## Today
- A replay (`.rpl`) is not a video: it stores the commands given per game segment, the map checksum, the start scenario tracker and the multiplayer settings (`Sources/src/Main/CommandsHistory.cpp`), and playback runs the mission again from them.
- Saving: the mission statistics screen has a hidden "Save Replay" button (`Data/UI/Stats.xml`, element 10003, `VisibleFlag="0"`). `Stats.cpp:489` shows it only when `MultiplayerGame == 1` and no replay is playing. It opens `ui\Popup\SaveReplay` and writes `<profile>\replays\<name>.rpl` (`mods\<mod>\replays\` with a mod active).
- Playing: Main Menu, Load Game, "Load Replay Demo" (`UIState.cpp:319`, `ReplayList.cpp`). The list starts a single-player transceiver when the replay is not a multiplayer one (`ReplayList.cpp:45-48`), and returns to the list when the replay ends.
- Recording runs in single-player too: `SinglePlayerTransceiver.cpp:63-124` adds every command to the history and executes a loaded history.
- Developer flags: `-sh<file>` saves the history at exit, `-lh<file>` / `-lhclient<file>` play one back (`GameMain.cpp:2194-2217`).

## Why single-player replays would drift today
Playback zeroes the random seed (`CommandsHistory.cpp:102-104`). Multiplayer zeroes it at game start as well (`GamePlaying.cpp:36-38`, `111-113`), so recording and playback start alike. Single-player does not: its recording starts from whatever seed the game has, so hits, misses and AI choices would differ on playback. The history already keeps the start seed (`pStartRandomSeed`, captured in `PrepareToStartMission`), but saving it into the replay and restoring it is commented out (`CommandsHistory.cpp:96-101`, `167-171`, key `RandomSeed01`).

## What it needs
1. The start seed: store `pStartRandomSeed` in the replay and restore it on load (the commented-out code), or zero the seed at single-player mission start as multiplayer does. Keep reading old multiplayer replays.
2. The button: show "Save Replay" after single-player missions too (`Stats.cpp:489`).
3. The proof: a headless tier that plays a mission with a scripted set of commands, saves the replay, plays it back and compares the end state by code (units alive, losses, mission outcome, the final segment). Runs in CI on every platform.

## Risks to check
- Anything that draws from the C runtime's `rand()` instead of `IRandomGen` (as the map editor's field fill did, fixed on fix/m3-fields-flake) breaks the replay.
- Campaign missions: units and upgrades carried in by the scenario tracker; the replay stores the start tracker, never tested in single-player.
- A mission saved and loaded partway: the history is part of the save (`CCommandsHistory::operator&`), so the replay should still start at the mission start; test it.
- Game speed changes and pauses during the mission.
- Replays from the original game or Steam (`D:\SteamLibrary` on win-home) only load with identical map and resource checksums.
