# 06 Oracle runbook: MFC batch export on win-home

Purpose: the maintainer runs the legacy MFC `editor.exe` on win-home over the repo-owned fixtures and commits the
exported trees as goldens. The portable Resource Editor (plans 06-03 onward) is compared against them. The Linux agent
cannot run `editor.exe`; it only reads the committed goldens.

## (a) Command line

Confirmed from `CEditorApp::RunBatchMode` in `Sources/src/editor/editor.cpp` (the Batch mode dialog,
`BatchModeDialog.cpp`, exposes the same four inputs: search mask, source dir, dest dir, Force and Open-and-save flags):

```
editor.exe <ext> <src-dir> <dst-dir> [-f] [-os]
```

- `<ext>` is one project extension (no dot). The legacy editor accepts exactly one per run and has NO `all` mode.
  The `all` mode in spec D-15 (`ResourceEditor --batch all <src> <dst>`) belongs to the new editor only, so on
  win-home the maintainer loops over the 21 extensions below, one `editor.exe` run each.
- `-f` forces export of everything regardless of timestamps. Always pass it for goldens.
- `-os` only opens and re-saves projects (no export). Do NOT pass it for the export goldens; run it separately only if
  a re-save golden is wanted (`golden-os/`, optional, same layout).
- Fewer than 4 arguments shows a usage message box and does not run; an unknown `<ext>` shows an error box.

Per extension (PowerShell, from the repo root, `editor.exe` from the win-home MFC build):

```
foreach ($e in '3rd','3rv','bdg','bld','cgc','chc','eff','fnc','gui','mcp','mdc','mip','msh','obt','pcp','scp','spt','til','trc','unt','wpn') {
  $src = "tools\zig\fixtures\resource_editor\$e"
  $dst = "tools\zig\fixtures\resource_editor\$e\golden"
  & .\editor.exe $e $src $dst -f
}
```

## (b) Input tree

`tools/zig/fixtures/resource_editor/<ext>/` holds `project.<ext>` plus its placeholder art (see
`tools/zig/fixtures/resource_editor/EXTENSIONS.md` for the art file and hash per extension). Inputs are generated by
`zig build make-resource-fixtures`; never edit by hand. The `golden/` directory is inside the source directory, so the
exporter must be given the clean fixture directory; delete any previous `golden/` content first (keep `.gitkeep`)
so old output is not re-read as input.

## (c) Output layout to commit

One golden tree per extension, exactly as the exporter writes it, under
`tools/zig/fixtures/resource_editor/<ext>/golden/`. Do not rename or flatten. Keep `.gitkeep`. Commit with
`test(resource-editor): MFC oracle goldens for <ext>` (one commit per extension or one for all).

## (d) Exclusions

- Goldens from GOG or other mod data live on win-home only and are never committed.
- Only repo-owned fixture inputs produce committed goldens. No shipped `Data/` is read or written.
- Do not commit the editor's own settings, registry exports or logs (`gamma.cfg` reports excepted if generated inside
  `golden/`).

## (f) Re-producing goldens

1. Regenerate fixtures: `zig build make-resource-fixtures` (Linux or win-home) and commit changed fixtures.
2. On win-home, empty each `<ext>/golden/` except `.gitkeep`, then rerun the loop in (a).
3. Review `git diff --stat` per extension; only extensions whose fixtures changed should change.
4. Commit the goldens. Whenever the generator changes, rerun for all 21.
