# 999.5 Windows arm64 target and CI job — notes

Captured 2026-10-08 together with 999.4. Decision: backlog.

## Today
No Windows arm64 build. `build.zig`'s target check accepts x86_64-windows-msvc, x86_64-windows-gnu, x86_64-linux-gnu, aarch64-linux-gnu, x86_64-macos and aarch64-macos only.

## What it needs
1. `aarch64-windows-msvc` in `build_support.classify` and wherever the Windows target is matched by architecture (MSVC/SDK lib paths are `...\lib\arm64` and `...\Lib\<ver>\um\arm64`, `ucrt\arm64`).
2. The arm64 MSVC libraries: Visual Studio component `Microsoft.VisualStudio.Component.VC.Tools.ARM64`; check it is on the `windows-11-arm` image (or on `windows-latest`, to cross-compile from x64).
3. A build to find x86-only engine code: SSE/x86 intrinsics, inline `__asm`, `_M_IX86`/`_M_X64` assumptions, and vendored libraries without arm64 support.
4. A job on `windows-11-arm` (hosted, free for public repositories): the GPU probe decides whether the engine-hosted tiers can run there or must skip honestly.

## Order
Build first and size the port; add the CI job once the game builds. Consider doing it together with 999.3 (MinGW), since both touch the Windows target matching in `build.zig`.
