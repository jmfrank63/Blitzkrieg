# 999.1 Random map generation: fast polygon fill — notes

Captured 2026-09-29 from Johannes's observation in the CI random missions tier (debug asserts, Windows): finding polygons is almost instant, filling takes up to ~25 s.

## Measured (CI run 36444961793, windows-platform, "Random missions tier (debug asserts)", kharkov42, 16 maps)
- `CreateRandomMap. Find Polygons.` 0–1 ms
- `CreateRandomMap. Fill polygons.` min 2552 ms, median 10207 ms, max 15144 ms
- The release sweep prints no timings (quiet release logging), so release cost is unknown.

## Where the time goes (code reading, to be confirmed by measurement)
`Sources/src/RandomMapGen/MapInfo_StaticMethods_RMGeneration.cpp`, the fill loop ~1708–1770, `FillTileSet` ~450, `FillObjectSet` ~556, `FillProfilePattern` after it, `GetInclusivePolygonSetDistance` ~346.
- Every inclusive/exclusive polygon is first run through `RandomizeEdges` (up to 100 subdivisions per edge), so polygons carry hundreds to thousands of points, kept in `std::list`.
- For every cell on the polygon's scanlines, `GetInclusivePolygonSetDistance` does `ClassifyPolygon` on the inclusive polygon (O(V)), `PolygonDistance` to it (O(V)) and `PolygonDistance` to every exclusive polygon (O(V_e)): cost ~ cells × vertices.
- `FillTileSet` computes it per tile and caches it in `distances`; `FillObjectSet` recomputes it on the half-tile grid (4× the cells) without the cache; `FillProfilePattern` reuses the cache.
- The `ClassifyPolygon` test is redundant: the scanline (`GetPolygonLine`) already put the cell inside.
- MSVC debug checked iterators (`_STL_RANGE_CHECK`, iterator debugging) make the `std::list` walks much slower in debug.

## Proposed order
1. Measure: split the timer into FillTileSet / FillObjectSet / FillProfilePattern; profile a release build locally (tools/profile/flamegraph.sh). Decide whether release players wait noticeably or it is mainly CI time.
2. Determinism gate first: generate the sweep's maps before and after with fixed seeds and require byte-identical .bzm output.
3. Cheap: polygons to `std::vector` once per area; drop the redundant ClassifyPolygon; let FillObjectSet reuse cached distances where cells align.
4. Structural (only if the numbers call for it): distances matter only up to the summed shell width; index edges in a coarse grid and query only edges within that width; scanline spans for exclusive polygons. cells × vertices → cells × nearby edges. Keep float arithmetic order so results stay identical.
