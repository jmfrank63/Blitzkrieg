このリポジトリは Johannes Maria Frank の個人的な趣味のプロジェクトです。楽しみと学習のために使っていて、特に既存アプリケーション(ブラウンフィールド)でのエージェント型コーディングの練習が目的です。元の README は `readme_original` に残してあります。

注意:このプロジェクトは開発途中です。


# プロジェクトの現状(2026年11月)

移植そのものはほぼ終わりました。ゲームは Windows、macOS、Linux でネイティブに動き、10 言語に対応し、エディタもすべて移植済みです。今は、建物や小物を向きを変えて見せるためのアートワークで行き詰まっています。下の「壁:アートワーク」を見てください。


# これまでにやったこと

**ゲーム**

- シングルプレイヤー用のゲーム全体とそのデータがそろっていて、`zig build`(Zig + clang)でネイティブの 64 ビットプログラムとしてビルドします。キャンペーン、直感操作ガイド、ランダムミッションをプレイでき、セーブ/ロード、ビデオ、サウンドも使えます。

- エンジンを Win32 と DirectX から移植可能な層に移しました。ウィンドウ、入力、オーディオには SDL3、描画には SDL GPU レンダラーを使います。

- クローズドなライブラリはなくなりました。FMOD、Bink、Stingray を取り除き、サウンドとムービーは Ogg Vorbis と Ogg Theora を使います。

- エンジンの永続化層である StreamIO.dll は、Zig 実装に置き換えました(`Sources/src/StreamIOZig`)。

- 従来の C++ を clang と UBSan でコンパイルし、2003 年のビルドが黙って見過ごしていた数十件のバグを見つけて直しました。

- 元のランダムミッションを復活させ、各キャンペーンの章は、スクリプトの意図どおりに対応する史実のミッションを解放します。

- プレイヤープロファイルは、クラウド同期でマシン間を持ち運べます。

- LAN マルチプレイが動きます。GameSpy のコードは取り除いたので、インターネット対戦はまだつながっていません。

**10 言語**

- ゲーム、すべてのエディタ、コマンドラインツールとそのガイド、そしてこの README を、英語、ロシア語、中国語(簡体字)、ヒンディー語、スペイン語、フランス語、ドイツ語、ポルトガル語(ブラジル)、日本語、インドネシア語で読めます。

- 英語以外の 9 言語は言語 mod としてインストールします。新しい TrueType テキストエンジンが、これらすべての文字体系を描画します。

- 翻訳は機械翻訳で、ネイティブスピーカーによる確認がまだ必要です。修正は歓迎します。

**すべてのエディタ**

- マップエディタ、すべてのサブエディタを含むリソースエディタ、ローカライズキットの ELK を、Dear ImGui を使った Zig アプリとして書き直しました(`Sources/editor`)。C++ のエンジンとは C ABI を通じてやり取りします(`Sources/src/EditorBridge`)。

- Windows 専用だった古い MFC エディタは削除しました。新しいエディタが書き出したものをゲームがそのまま読めることは、ゲーム自身のリーダーを使ったテストで確かめています。

- 古いコマンドラインツールは、mod 作成用の 7 つの移植可能なツールに置き換えました。`bk-pak`、`bk-table`、`bk-image`、`bk-video`、`bk-font`、`bk-map`、`bk-sprite` です。`tools/guide/README.md` を見てください。

**Remastered オプション**

- 最適化オプション > 設定 > ゲームプレイ > Remastered は既定でオフで、オフなら元のルールで遊べます。オンにすると、カメラを 4 段階で回す、最速ルートの経路探索、歩兵をコンテナからコンテナへ直接移動させる、といった 2003 年のゲームにはなかった機能が加わります。

- ミッションのリプレイを作っているところで、土台部分はマージ済みです。


# 壁:アートワーク

カメラを回すには、すべての建物や小物を 4 方向から見せなければなりません。しかし 2003 年のアートは、各オブジェクトを一方向から見た絵の集まりでしかありません。ほかの面は一度も描かれていませんでした。

これまで、412 個すべてのオブジェクトについて 2 つの方法を試しました。

- 2003 年のピクセルから、向きを変えた絵を一枚ずつ作る方法(2026-10-29 にあきらめました。一つ解決するたびに、新しい問題が一つ出てきたからです)。

- 同じ絵から色を塗った簡単な 3D モデルをレンダリングする方法。今のプロジェクトはこれを使っています。2003 年のアートが見せている側は正しく見えますが、一度も見えていない部分はすべて推測するしかありません。細部もうまくいきません。平らな屋根に描かれた屋根窓は、別の方向から見るとおかしく見えます。

どちらも十分ではありません。正しいやり方は、オブジェクトごとに本物の 3D モデルを用意することです。屋根窓のような細部は本物の形状にし、平らな面ごとにテクスチャを貼れば、どの向きから見ても形から自然に決まります。

問題は、そのモデルとテクスチャをどこから手に入れるかです。

- 2003 年のデザインに沿って、手作業またはエージェントでモデリングする。

- Nival が公開した Blitzkrieg 2 のモデル。テストレンダリングで、この作りになっていて 4 方向のどこから見てもきれいに見えることは分かりましたが、同じ名前でも 2003 年のものとは別の建物が多く、ライセンスがそのアートまで明確にカバーしているとは言えません。

- 画像から 3D を生成するツール。このアートにはまだ試していません。

まだ何も決めていません。3D アーティストの方や、この種の作業に詳しい方は、ぜひ連絡をください。

# 対応プラットフォーム

ターゲットは `-Dtarget=` で指定します。生成されるツリーは `zig-out/game/<os>/<arch>/<config>` の形に配置されるので、複数のターゲットと両方の最適化レベルを並べて置けます。

| プラットフォーム | ターゲットトリプル | 状況 |
| --- | --- | --- |
| Windows (MSVC) | `x86_64-windows-msvc` | ゲームとエディタが動作。CI でテスト済み |
| macOS (Apple Silicon) | `aarch64-macos` | ゲームとエディタが動作。CI でテスト済み |
| Linux (x86_64) | `x86_64-linux-gnu` | ゲームとエディタが動作。CI ではソフトウェアレンダラーでテスト済み |
| macOS (Intel) | `x86_64-macos` | ビルド可能。CI のランナーには GPU がないためゲームは動かせず、ゲームは実機の Intel Mac で確認 |
| Linux (arm64, Raspberry Pi) | `aarch64-linux-gnu` | プラットフォームのテストのみ。ゲームとエディタは未テスト |
| Windows (MinGW) | `x86_64-windows-gnu` | プラットフォームのテストのみ。エンジンはまだここではコンパイルできない |

CI は各ターゲットを自身のアーキテクチャのランナーで実行するので、スイートは単にリンクされるのではなく実際に動作します。現在、Linux と macOS の一部のジョブが失敗しています。

Linux ではウィンドウアイコンをプログラム内で設定していて、X11 と KDE はこれを反映します。Wayland 上の GNOME はこれを無視し、Dock と Alt+Tab のアイコンを、プログラムのアプリ ID にちなんだ名前のデスクトップエントリから取ります(ゲームは `org.blitzkrieg.game`、エディタは `org.blitzkrieg.mapeditor`、`org.blitzkrieg.resourceeditor`、`org.blitzkrieg.elk` です)。インストールには、これらのエントリとアイコンを `~/.local/share` に書き込む、任意で使うスクリプトが付いていますが、自動では実行されません。インストールフォルダから `Tools/install_desktop_entry.sh` を実行してください(チェックアウトからなら `tools/install_desktop_entry.sh [install-dir]`)。`Tools/install_desktop_entry.sh --remove` で元に戻せます。

Visual Studio のインストールが必要なのは `x86_64-windows-msvc` だけです。MinGW を含むそれ以外のターゲットでは、Zig が独自のツールチェーン、ヘッダー、インポートライブラリを提供します。


# ビルドと実行

1. サブモジュール付きでリポジトリをクローンするか、既存のチェックアウトで `git submodule update --init --recursive` を実行します。

2. Zig 0.17 をインストールします。`x86_64-windows-msvc` には MSVC ツールチェーンと Windows SDK も必要です(`build.zig` の既定値と違う場合は、`-Dmsvc-include`/`-Dwindows-sdk-include` とそれぞれの `lib` 版でパスを設定できます)。

3. ゲーム、9 つの言語 mod、すべてのエディタをビルドするには `zig build install-all -Dtarget=<triple> --release=fast` を、ゲームだけなら `zig build install-game` を実行します。`-Dtarget` を省略するとホスト向けにビルドし、`--release=fast` を外すとデバッグビルドになります。

4. 生成されたバイナリを起動します。たとえば Windows なら `zig-out/game/windows/x86_64/release/Game.exe`、Apple Silicon なら `zig-out/game/macos/arm64/release/Game` です(`--release=fast` なしなら `.../debug/...`)。ゲームはウィンドウで動作し、`-fullscreen` がコマンドラインオプションとして使えます。

5. `zig build package` は配布用の zip パッケージを作り、`zig build --help` はすべてのステップとテストを一覧表示します。


# これまでの経緯

- 不足していたライブラリを見つけ、2003 年のソリューションを最新の Visual Studio でクリーンな状態からコンパイルできるようにして、最初の直感操作ガイドをプレイしました。

- ビルドを Zig に移しました。`build.zig` がすべてのプロジェクトを clang でコンパイルし、実行可能なゲーム構成を配置します。

- StreamIO.dll を Zig で置き換え、Zig ビルドでゲームを最初から最後までプレイできるようにしました。

- ゲームを 64 ビットに移植し、UBSan を使って直感操作ガイドをクラッシュごとにプレイテストしました。

- Win32 から SDL3 と SDL GPU レンダラーに移り、ゲームを macOS と Linux で立ち上げました。

- マップエディタ、リソースエディタ、ELK を移植し、MFC 版は削除しました。古いコマンドラインツールも置き換えました。

- FMOD、Bink、Stingray を取り除きました。

- テキストエンジンを追加し、ゲーム、エディタ、ツールで 10 言語に対応しました。

- Remastered オプションとカメラの回転を追加し、それが上で述べた壁につながりました。


# ロードマップ

1. アートワークの壁を越える。3D モデルとテクスチャをどこから手に入れるかを決め、許可が必要なものは許可を得る。

2. ミッションのリプレイを仕上げる。

3. すべての CI ジョブを再び通す。

4. Linux arm64 と MinGW でゲームとエディタを立ち上げ、Windows arm64 を加える。

5. GameSpy の代わりとなる OpenSpy 互換の仕組みで、インターネットマルチプレイをつなぐ。

6. 32 ビットのセーブデータを 64 ビット形式に変換するユーティリティを作る。

7. StreamIO の移植をひな形にして、C++ プロジェクトを引き続き Zig コードに置き換える。
